# 生成、输入准备与质量检查

## 提示词制作单

每次调用将配方写成针对当前照片的说明，不只是“韩系、可爱、高级”。可使用以下结构，删除不需要的部分：

```text
用途：一张完整手机壁纸，目标比例/尺寸，平面成品而非手机模型。
输入角色：图1/2…用户宠物身份与姿态；图N…版式/材质参考；图M…仅装饰；修改时注明目标成品。
主体：真实可见识别特征、原姿态与表情、原有衣服，指定物种解剖。
照片分配：源图→槽位、主辅大小、允许裁切；指定宠物全部出现。
风格：所选配方的底纸、边缘、装饰、配色和层次。
构图：主角位置、时钟低干扰区、脸/耳/尾边距、装饰叠压关系。
文字：逐字列出允许出现的全部文字；其余不得增加。或无文字。
保留：原照脸型、口鼻长度、眼距、斑纹、摄影纹理，不套参考宠物身体。
排除：原背景、人、牵引绳等非主体；参考宠物/衣服/名字/品牌、水印、系统界面。
```

坐标和尺寸是目标，需要检查输出；不能当作模型必然遵守的参数。局部修改指令也不是固定图层锁。

每个主风格调用独立生成，传入当前用户原照。不要先把宠物生成一次，再把生成图反复重绘成所有风格。需要透明贴纸时才单独制作，不为了“稳定”无目的增加中间生成。

## 原图与参考输入

本技能的 `references/images` 是视觉参考，不是可直接粘贴的透明素材。元素板均带底色，即使来源扩展名为 PNG 也不代表透明；白色蕾丝、丝带与奶油物件不能简单删除白色背景。

内置参考已做方向/编码整理并验证能解码。仍需查看选定参考。成品参考里本来有别的宠物与部分截图界面；在输入角色和提示词里明确只借版式，不借身份和文字。

遇到输入无法读取时，区分路径不存在、图片损坏、传输限制；不要无限原样重试或跳过关键身份图。可制作非破坏性的传输副本：按 EXIF 方向转正、重新编码、必要时缩小到仍足够看清脸部的尺寸，原文件保留。此步骤仅为工具读取准备，不用于通过脚本改变宠物外观或替代生图。含 alpha 的用户图保留透明通道；不要一律转 JPEG。查看准备后的副本再提交，记录处理。

输出工具返回图片及文件路径时，通过支持的图片输出方式展示；不要把 base64 数据打印成文本。将选定成品复制到项目输出目录，保留工具原文件。不要猜测不存在的保存参数或工具能力。

## 验收

先检查必须通过项：

1. 身份：没有串脸或参考宠物，指定宠物均出现，关键斑纹/耳形/口鼻长度仍匹配。
2. 来源：各照片保持实际表情/姿态，没有伪造未拍摄的腿、身体或配饰；如果单图复用，记录清楚。
3. 内容：名字和指定文字逐字正确，无系统时间、电量、相机/手电图标、平台水印或作者签名。无文字请求不得含额外标题/小字。
4. 文件：每个承诺款式都有独立图片；文件能解码；真实宽高已读出；不把未达目标尺寸称为“精确适配”。

然后看设计：

- 能一眼分辨对应 A/B/D 三种风格，尤其 B 与 D 的边缘/装饰/疏密差别。
- 主辅明确，文字/物件不抢脸，阴影像贴纸而非塑料浮雕。
- 白毛不融底、黑毛不死黑，毛发不会因锐化变插画。
- 眼鼻与重要耳部不贴边，不被物件遮挡；顶部低干扰，底部留有实机裁切余量。
- D 主体不过大且保留留白。

照片相似度是视觉判断，不编造相似度百分比。只有当前样本的观察，不推断所有物种已验证。无法肯定的问题直接列为待检查。

## 返修

一个修正轮次聚焦一个具体问题，携带原用户照片、选定成品和必要参考；重复关键身份不变量。局部修改后检查全图，因为另一张脸、衣服或文字也可能改变。

明确身份/肢体错误优先修；单纯装饰偏好无需无限润饰。连续两次针对同一问题仍无改善时，停止机械重试，保留版本，说明实际限制和可行替代（例如更紧裁切、少图版式）。不把不合格图说成成功；用户追加明确修正时可以继续。

尺寸目标失配时先检查实际比例，可请求生图重新构图/扩展；不能直接拉伸宠物。若需要程序化原照抠图、逐像素保真或精确导出，应明确这属于另一种实现方式，只在用户明确选择后采用。本技能提供的是内置生图流程，不能仅写提示词就承诺原照完全不变。

记录可为一个 Markdown/JSON 文件，不强制每款另建许多文件。用户名、宠物身份和路径只保留在本任务输出记录，不写回共享技能或后续用户的提示词。
